## What Is Backtracking?

Imagine you're in a maze. At every fork, you pick a direction and keep going. If you hit a dead end, you **go back** to the last fork and try the other direction. That's backtracking!

In coding terms, backtracking is a refined form of recursion where you:
1. **Choose** — pick an option to explore
2. **Explore** — recurse deeper with that choice
3. **Un-choose (backtrack)** — undo that choice and try the next option

This technique is perfect for problems that ask you to find **all** combinations, permutations, or subsets. It's like a systematic trial-and-error approach that guarantees you explore every possibility without repeating work.

## The Problem: Subsets (LeetCode #78)

**Problem:** Given an integer array `nums` of unique elements, return all possible subsets (the power set). The solution must not contain duplicate subsets.

**Example:**
- Input: `nums = [1, 2, 3]`
- Output: `[[], [1], [2], [3], [1,2], [1,3], [2,3], [1,2,3]]`

Think of it like ordering at a restaurant where each item is optional. For every item, you either **include it** or **skip it**. With 3 items, you have 2 × 2 × 2 = 8 possible meals (including ordering nothing).

**Why this matters:** Subsets is the "Hello World" of backtracking. Once you understand this pattern, you can solve dozens of similar problems (combinations, permutations, partition problems, etc.).

## Visualizing the Decision Tree

For `nums = [1, 2, 3]`, imagine a tree where at each level you decide about one number:

```
                    []
                /        \
           [1]              []
          /    \          /    \
       [1,2]   [1]     [2]     []
       / \     / \     / \    / \
  [1,2,3][1,2][1,3][1][2,3][2][3][]
```

- **Level 0:** Do I include 1? Yes → go left, No → go right
- **Level 1:** Do I include 2?
- **Level 2:** Do I include 3?
- **Leaf nodes** (bottom) = all 8 subsets!

Each path from root to leaf represents one subset. The backtracking happens when we finish one branch, **remove the last element**, and explore the next branch.

## Solution: Backtracking Approach

```python
def subsets(nums):
    result = []       # stores all subsets
    current = []      # the subset we're currently building
    
    def backtrack(start):
        # Every call represents a valid subset — add a COPY to result
        result.append(current.copy())
        
        # Try adding each remaining number
        for i in range(start, len(nums)):
            # CHOOSE: add nums[i] to current subset
            current.append(nums[i])
            
            # EXPLORE: recurse with next index (no repeats)
            backtrack(i + 1)
            
            # UN-CHOOSE (BACKTRACK): remove nums[i] to try next option
            current.pop()
    
    backtrack(0)
    return result

# Test it
print(subsets([1, 2, 3]))
# Output: [[], [1], [1,2], [1,2,3], [1,3], [2], [2,3], [3]]

# Let's trace through to understand:
# backtrack(0): current=[] → add [] to result
#   i=0: current=[1] → add [1]
#     i=1: current=[1,2] → add [1,2]
#       i=2: current=[1,2,3] → add [1,2,3]
#       pop → current=[1,2]
#     pop → current=[1]
#     i=2: current=[1,3] → add [1,3]
#     pop → current=[1]
#   pop → current=[]
#   i=1: current=[2] → add [2]
#     i=2: current=[2,3] → add [2,3]
#     pop → current=[2]
#   pop → current=[]
#   i=2: current=[3] → add [3]
#   pop → current=[]
```

## The Backtracking Template You Can Reuse

Almost every backtracking problem follows this skeleton:

```
def backtrack(state, choices):
    if goal_reached(state):
        save_result(state)
        return
    
    for choice in choices:
        if is_valid(choice):       # optional pruning
            make_choice(state)     # choose
            backtrack(new_state)   # explore
            undo_choice(state)     # un-choose
```

**Key details for Subsets:**
- We use `start` index to avoid picking the same element or creating duplicates like `[2,1]` when we already have `[1,2]`
- We add to result at **every** recursive call (not just leaf nodes) because every partial subset is valid
- `current.copy()` is critical — without it, all entries in `result` would reference the same list that ends up empty

**Time & Space Complexity:**
- **Time:** O(n × 2^n) — there are 2^n subsets, and copying each takes up to O(n)
- **Space:** O(n) for the recursion stack depth (not counting the output)

## Key Takeaways

- Backtracking follows a Choose → Explore → Un-choose pattern, systematically exploring all possibilities by undoing choices after each recursive call.
- The Subsets problem is the foundational backtracking problem — use the `start` index to avoid duplicates, and add a copy of the current state at every step.
- Always use `.copy()` when saving a mutable list to your results; otherwise you'll end up with references to the same (eventually empty) list.
- The backtracking template (state + choices + recurse + undo) applies to many problems: combinations, permutations, N-Queens, Sudoku, and more.
