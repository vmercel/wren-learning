## The Phone Book Analogy

Imagine you're looking up "Martinez" in a phone book with 1,000 pages. You wouldn't start at page 1 and flip one page at a time — that could take 1,000 flips!

Instead, you'd:
1. **Open to the middle** (~page 500). You see names starting with "M" — close!
2. **Decide: go left or right?** "Martinez" comes after "M-a-b", so go slightly right.
3. **Open to the middle of the remaining section** and repeat.

Each step **cuts your search space in half**. With 1,000 pages:
- After 1 step: 500 pages left
- After 2 steps: 250 pages left
- After 10 steps: ~1 page left

That's **10 steps instead of 1,000**. This is binary search — it works on any **sorted** collection.

## The Binary Search Template

Binary search uses three pointers:
- **left** — the start of your search range
- **right** — the end of your search range
- **mid** — the middle point you check each time

The algorithm:
1. Set `left = 0` and `right = len(array) - 1`
2. While `left <= right`:
   - Calculate `mid = (left + right) // 2`
   - If `array[mid] == target`: **found it!** Return `mid`
   - If `array[mid] < target`: target is to the right, so `left = mid + 1`
   - If `array[mid] > target`: target is to the left, so `right = mid - 1`
3. If the loop ends without finding: return `-1`

**Key requirement**: The data **must be sorted** for binary search to work.

## Basic Binary Search Implementation

```python
def binary_search(nums, target):
    left = 0
    right = len(nums) - 1
    
    while left <= right:
        mid = (left + right) // 2  # Find the middle index
        
        if nums[mid] == target:
            return mid              # Found it! Return the index
        elif nums[mid] < target:
            left = mid + 1          # Target is in the right half
        else:
            right = mid - 1         # Target is in the left half
    
    return -1  # Target not found

# Example walkthrough:
nums = [1, 3, 5, 7, 9, 11, 13]
target = 9

# Step 1: left=0, right=6, mid=3 → nums[3]=7 < 9 → go right
# Step 2: left=4, right=6, mid=5 → nums[5]=11 > 9 → go left  
# Step 3: left=4, right=4, mid=4 → nums[4]=9 == 9 → Found at index 4!

print(binary_search(nums, 9))   # Output: 4
print(binary_search(nums, 6))   # Output: -1 (not found)
```

## LeetCode #704: Binary Search

**Problem**: Given a sorted array of integers `nums` and a target value `target`, return the index if found, or `-1` if not.

**Constraints**:
- All elements are **unique**
- Array is sorted in **ascending order**
- Must run in **O(log n)** time

This is exactly what our template does! But let's think about **common mistakes**:

1. **Using `left < right` instead of `left <= right`** — This skips checking when left equals right (a single element remaining). You'd miss valid answers.
2. **Setting `right = mid` instead of `right = mid - 1`** — This can cause infinite loops because you never shrink the search space.
3. **Integer overflow with `(left + right) // 2`** — In Python this isn't an issue (Python handles big integers), but in languages like Java/C++, use `left + (right - left) // 2` instead.

## LeetCode #35: Search Insert Position (A Step Further)

```python
# Problem: Given a sorted array and a target, return the index if found.
# If not found, return the index WHERE IT WOULD BE INSERTED.
# Example: nums = [1,3,5,6], target = 4 → return 2 (between 3 and 5)

def searchInsert(nums, target):
    left = 0
    right = len(nums) - 1
    
    while left <= right:
        mid = (left + right) // 2
        
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    
    # When target is NOT found, 'left' is exactly where it should be inserted!
    return left

# Why does 'left' give the insert position?
# When the loop ends, left > right.
# 'left' points to the first element GREATER than target — perfect insert spot.

print(searchInsert([1, 3, 5, 6], 5))   # Output: 2 (found)
print(searchInsert([1, 3, 5, 6], 4))   # Output: 2 (insert before 5)
print(searchInsert([1, 3, 5, 6], 7))   # Output: 4 (insert at end)
print(searchInsert([1, 3, 5, 6], 0))   # Output: 0 (insert at beginning)
```

## When to Use Binary Search

Use binary search whenever you see these clues:

- The input is **sorted** (or can be sorted)
- The problem asks you to **find a specific value** or a **boundary** (first/last occurrence)
- The problem requires **O(log n)** time complexity
- You're searching for the **minimum/maximum value that satisfies a condition** (advanced usage)

**Time complexity comparison**:
| Array Size | Linear Search (O(n)) | Binary Search (O(log n)) |
|---|---|---|
| 100 | 100 steps | 7 steps |
| 1,000 | 1,000 steps | 10 steps |
| 1,000,000 | 1,000,000 steps | 20 steps |

Binary search is dramatically faster on large datasets. This is why it comes up so often in interviews — it shows you understand how to write efficient code.

## Key Takeaways

- Binary search cuts the search space in half each step, giving O(log n) time — exponentially faster than scanning every element.
- The template has three critical parts: initialize left/right, calculate mid, and update left or right based on comparison. Always use `left <= right` to avoid skipping elements.
- When the target isn't found, the `left` pointer ends up at the correct insertion position — this insight solves many binary search variants.
- Binary search ONLY works on sorted data. If the array isn't sorted, sort it first (O(n log n)) or use a different approach.
