> Backtracking is a powerful technique for exploring all possible combinations, permutations, or subsets. In this lesson, we tackle the classic 'Subsets' problem (LeetCode #78) to learn how backtracking builds solutions incrementally and undoes choices to explore every path.

## What Is Backtracking?

Imagine you're in a maze. At every fork, you pick a direction. If you hit a dead end, you **go back** to the last fork and try the other direction. That's backtracking!

In programming terms, backtracking means:
1. **Make a choice** (add an element, pick a path)
2. **Explore** further with that choice
3. **Undo the choice** (backtrack) and try the next option

This is different from the greedy or dynamic programming approaches we've seen before. Backtracking systematically explores **all possibilities**, which makes it perfect for problems that ask you to generate all combinations, permutations, or subsets.

**When to use backtracking:**
- The problem says "find all", "generate all", or "list every"
- You need to explore multiple decisions at each step
- The solution is built piece by piece

## The Problem: Subsets (LeetCode #78)

**Problem:** Given an integer array `nums` of unique elements, return all possible subsets (the power set). The solution must not contain duplicate subsets.

**Example:**
- Input: `nums = [1, 2, 3]`
- Output: `[[], [1], [2], [3], [1,2], [1,3], [2,3], [1,2,3]]`

Think of it this way: for each number, you have exactly **two choices** — include it or skip it. If you have 3 numbers, that's 2 × 2 × 2 = 8 possible subsets. This is why the result is called the **power set**.

**Analogy:** Imagine you're at a buffet with 3 dishes. For each dish, you either put it on your plate or skip it. The collection of every possible plate combination is what we're generating.

## Visualizing the Decision Tree

For `nums = [1, 2, 3]`, picture a tree where each level represents a decision about one number:

```
                    []
                /        \
           [1]              []
          /    \          /    \
      [1,2]   [1]      [2]     []
      / \     / \      / \    / \
 [1,2,3][1,2][1,3][1] [2,3][2][3] []
```

At each level, we decide: **include the current number (go left)** or **skip it (go right)**.

Every leaf node at the bottom is a valid subset. Our backtracking algorithm walks through this tree, collecting results at each leaf.

Another way to think about it: instead of include/skip, we can loop through remaining elements starting from a given index, adding one element at a time and recursing deeper.

## Solution: Backtracking Approach

```python
def subsets(nums):
    result = []
    
    def backtrack(start, current_subset):
        # Every call represents a valid subset — add a copy to result
        result.append(current_subset[:])
        
        # Try adding each remaining element
        for i in range(start, len(nums)):
            # CHOOSE: add nums[i] to the current subset
            current_subset.append(nums[i])
            
            # EXPLORE: recurse with the next index
            backtrack(i + 1, current_subset)
            
            # UN-CHOOSE (backtrack): remove nums[i]
            current_subset.pop()
    
    backtrack(0, [])
    return result

# Test it
print(subsets([1, 2, 3]))
# Output: [[], [1], [1,2], [1,2,3], [1,3], [2], [2,3], [3]]

# Let's trace through to understand:
# backtrack(0, [])        -> adds []
#   backtrack(1, [1])     -> adds [1]
#     backtrack(2, [1,2]) -> adds [1,2]
#       backtrack(3, [1,2,3]) -> adds [1,2,3], loop ends
#     backtrack(3, [1,3]) -> adds [1,3], loop ends
#   backtrack(2, [2])     -> adds [2]
#     backtrack(3, [2,3]) -> adds [2,3], loop ends
#   backtrack(3, [3])     -> adds [3], loop ends
```

## Breaking Down the Key Ideas

Let's understand each critical piece:

**1. Why `current_subset[:]` instead of `current_subset`?**
Lists in Python are passed by reference. If we append `current_subset` directly, all entries in `result` would point to the **same list**, which keeps changing. The `[:]` creates a snapshot (copy) at that moment.

**2. Why `start = i + 1`?**
This prevents us from reusing elements we've already considered. If we're looking at index 2, we only consider index 3 and beyond. This avoids duplicates like `[2, 1]` when we already have `[1, 2]`.

**3. The backtrack step: `current_subset.pop()`**
This is the heart of backtracking. After exploring all subsets that include `nums[i]`, we remove it so we can try the next element cleanly. It's like taking a dish off your buffet plate to make room for a different one.

**4. Time complexity: O(n × 2^n)**
There are 2^n subsets, and copying each subset takes up to O(n) time.

**5. Space complexity: O(n)**
The recursion depth is at most n (not counting the output storage).

## Key Takeaways

- Backtracking follows a pattern: CHOOSE → EXPLORE → UN-CHOOSE. You make a decision, recurse deeper, then undo the decision to try alternatives.
- The 'start' parameter is crucial — it prevents revisiting earlier elements and ensures each subset is unique.
- Always append a copy of your current state (e.g., current_subset[:]) to the result, not the mutable list itself.
- Backtracking is ideal for 'generate all' problems: subsets, permutations, combinations, and constraint satisfaction puzzles.
- A set of n elements produces exactly 2^n subsets — this helps you verify your solution's correctness.
