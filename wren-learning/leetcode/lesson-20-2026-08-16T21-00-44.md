> Binary search is one of the most powerful techniques in coding interviews. Instead of checking every element one by one, you repeatedly cut the search space in half, turning slow O(n) searches into blazing fast O(log n) lookups. This lesson teaches you the pattern through classic LeetCode problems.

## Why Binary Search Is a Game Changer

Imagine you're looking for a word in a dictionary. You wouldn't start at page 1 and read every page — you'd open to the middle, see if your word comes before or after, and then focus on just that half. That's binary search!

In our previous lessons, we've solved problems using hash maps (O(n) space) and two pointers (O(1) space on sorted data). Binary search gives us another superpower: **finding things in O(log n) time** — meaning in a list of 1,000,000 items, you only need about 20 checks!

| Approach | Time | When to Use |
|----------|------|-------------|
| Linear scan | O(n) | Unsorted data, no better option |
| Hash map lookup | O(1) | Need instant access, can use extra space |
| **Binary search** | **O(log n)** | **Data is sorted or answer space is monotonic** |

## The Binary Search Template You Should Memorize

Every binary search follows the same skeleton:

1. **Set boundaries**: `left` and `right` pointers marking the search range
2. **Find the middle**: `mid = left + (right - left) // 2`
3. **Make a decision**: Is `mid` the answer? Should we go left or right?
4. **Shrink the range**: Move `left` or `right` to cut the search space in half
5. **Repeat** until the range is empty

**Why `left + (right - left) // 2` instead of `(left + right) // 2`?**
They give the same result, but the first version avoids integer overflow in languages like Java/C++. It's a good habit even in Python.

**The trickiest part** of binary search is getting the boundary conditions right — when to use `<` vs `<=`, and when to set `right = mid` vs `right = mid - 1`. We'll address this with clear patterns.

## Problem: Classic Binary Search (LeetCode #704)

```python
# LeetCode 704: Binary Search
# Given a sorted array and a target, return its index or -1

def search(nums, target):
    left, right = 0, len(nums) - 1
    
    while left <= right:  # Note: <= because both left and right are valid indices
        mid = left + (right - left) // 2
        
        if nums[mid] == target:
            return mid          # Found it!
        elif nums[mid] < target:
            left = mid + 1      # Target is in the right half
        else:
            right = mid - 1     # Target is in the left half
    
    return -1  # Target not found

# Walk through example: nums = [1, 3, 5, 7, 9, 11], target = 7
# Step 1: left=0, right=5, mid=2 → nums[2]=5 < 7 → left=3
# Step 2: left=3, right=5, mid=4 → nums[4]=9 > 7 → right=3
# Step 3: left=3, right=3, mid=3 → nums[3]=7 == 7 → return 3 ✓

print(search([1, 3, 5, 7, 9, 11], 7))   # Output: 3
print(search([1, 3, 5, 7, 9, 11], 4))   # Output: -1
print(search([2, 5], 5))                 # Output: 1
```

## Problem: Search Insert Position (LeetCode #35)

```python
# LeetCode 35: Search Insert Position
# Given a sorted array and a target, return the index where it would be inserted
# This is a variation: find the FIRST position where nums[pos] >= target

def searchInsert(nums, target):
    left, right = 0, len(nums)  # Note: right = len(nums), not len(nums)-1
                                 # because the insert position could be at the end
    
    while left < right:  # Note: < not <= (different template!)
        mid = left + (right - left) // 2
        
        if nums[mid] >= target:
            right = mid      # mid could be the answer, don't skip it
        else:
            left = mid + 1   # mid is too small, skip it
    
    return left  # left == right, this is our insert position

# Example: nums = [1, 3, 5, 6], target = 5
# Step 1: left=0, right=4, mid=2 → nums[2]=5 >= 5 → right=2
# Step 2: left=0, right=2, mid=1 → nums[1]=3 < 5  → left=2
# left == right == 2 → return 2 ✓

# Example: nums = [1, 3, 5, 6], target = 2
# Step 1: left=0, right=4, mid=2 → nums[2]=5 >= 2 → right=2
# Step 2: left=0, right=2, mid=1 → nums[1]=3 >= 2 → right=1
# Step 3: left=0, right=1, mid=0 → nums[0]=1 < 2  → left=1
# left == right == 1 → return 1 ✓ (insert 2 at index 1)

print(searchInsert([1, 3, 5, 6], 5))  # Output: 2
print(searchInsert([1, 3, 5, 6], 2))  # Output: 1
print(searchInsert([1, 3, 5, 6], 7))  # Output: 4
print(searchInsert([1, 3, 5, 6], 0))  # Output: 0
```

## The Two Templates: Know When to Use Which

This is the most important section — understanding the two main binary search templates:

### Template 1: Exact Match (`left <= right`)
```
left, right = 0, len(nums) - 1
while left <= right:
    mid = left + (right - left) // 2
    if found: return mid
    elif go_right: left = mid + 1
    else: right = mid - 1
return -1
```
Use when: You're looking for an **exact value** and return as soon as you find it.

### Template 2: Boundary Finding (`left < right`)
```
left, right = 0, len(nums)  # or len(nums) - 1 depending on problem
while left < right:
    mid = left + (right - left) // 2
    if condition(mid): right = mid
    else: left = mid + 1
return left
```
Use when: You're looking for the **first/last position** where some condition is true. The answer is `left` (which equals `right`) when the loop ends.

### Quick Decision Guide:
- "Find the target" → Template 1
- "Find the first/smallest that satisfies..." → Template 2
- "Find the insert position" → Template 2
- "Find the boundary between true/false" → Template 2

## Key Takeaways

- Binary search works on sorted data and cuts the search space in half each step, giving O(log n) time — exponentially faster than linear scan
- Use Template 1 (left <= right) for exact match problems, and Template 2 (left < right) for boundary-finding problems
- Always use `mid = left + (right - left) // 2` to calculate the midpoint — it prevents overflow and is an interview best practice
- The key insight for binary search: if you can divide any problem into 'yes' and 'no' regions with a clear boundary, binary search can find that boundary
- Off-by-one errors are the #1 source of binary search bugs — trace through small examples (2-3 elements) to verify your boundaries
