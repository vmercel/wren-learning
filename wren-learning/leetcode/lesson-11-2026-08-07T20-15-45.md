## Why Hash Maps Are a Game-Changer

Imagine you have a phone book with 10,000 names. To find someone's number:

- **Without a hash map**: You might scan every entry one by one — that's O(n) time.
- **With a hash map**: You jump directly to the right entry — that's O(1) time.

A **hash map** (called a `dict` in Python) stores **key-value pairs**. You give it a key, and it instantly returns the associated value. Think of it like a real dictionary: you look up a word (key) and get its definition (value).

In previous lessons, we solved problems like Two Sum using nested loops (O(n²)). Hash maps let us solve the same problems in O(n) — a massive speedup!

**When to use a hash map:**
- You need to check "have I seen this before?"
- You need to count how many times something appears
- You need to find a pair/complement quickly
- You need to map one value to another

## Hash Map Basics in Python

```python
# Creating a hash map (dictionary)
phone_book = {}

# Adding key-value pairs
phone_book["Alice"] = "555-0101"
phone_book["Bob"] = "555-0202"
phone_book["Charlie"] = "555-0303"

# Looking up a value by key — O(1) instant!
print(phone_book["Bob"])  # "555-0202"

# Checking if a key exists — O(1)!
print("Alice" in phone_book)  # True
print("Zara" in phone_book)   # False

# Using .get() to avoid errors if key doesn't exist
print(phone_book.get("Zara", "Not found"))  # "Not found"

# Looping through all keys and values
for name, number in phone_book.items():
    print(f"{name}: {number}")
```

## Classic Problem: Two Sum (Revisited with Hash Map)

Back in earlier lessons, you may have solved Two Sum with nested loops. Let's now see the **optimal** hash map approach.

**Problem**: Given an array of numbers and a target, find two numbers that add up to the target. Return their indices.

**The key insight**: For each number `num`, its **complement** is `target - num`. Instead of scanning the entire array to find the complement, we store numbers we've already seen in a hash map and check instantly.

**Step-by-step thinking:**
1. Walk through the array one element at a time
2. For each number, calculate what number you *need* (the complement)
3. Check if that needed number is already in your hash map
4. If yes — you found your pair! If no — store the current number and move on

## Two Sum — Hash Map Solution

```python
def two_sum(nums, target):
    # Hash map: number -> its index
    seen = {}
    
    for i, num in enumerate(nums):
        complement = target - num
        
        # Have we seen the complement before?
        if complement in seen:
            return [seen[complement], i]
        
        # Store this number and its index for future lookups
        seen[num] = i
    
    return []  # No solution found

# Example walkthrough with nums = [2, 7, 11, 15], target = 9
# 
# i=0, num=2: complement=7, seen={} -> 7 not in seen -> seen={2:0}
# i=1, num=7: complement=2, seen={2:0} -> 2 IS in seen! -> return [0, 1]

print(two_sum([2, 7, 11, 15], 9))   # [0, 1]
print(two_sum([3, 2, 4], 6))         # [1, 2]
print(two_sum([3, 3], 6))            # [0, 1]
```

## Another Pattern: Counting with Hash Maps

One of the most common hash map patterns is **counting occurrences**. This is useful for problems like finding duplicates, checking anagrams, or finding the most frequent element.

**Problem: Contains Duplicate** — Given an array, return `True` if any value appears at least twice.

There are two approaches with hash maps:

## Contains Duplicate — Two Hash Map Approaches

```python
# Approach 1: Using a hash map as a "seen" set
def contains_duplicate(nums):
    seen = {}  # or use a set: seen = set()
    for num in nums:
        if num in seen:
            return True  # We've seen this number before!
        seen[num] = True
    return False

print(contains_duplicate([1, 2, 3, 1]))  # True
print(contains_duplicate([1, 2, 3, 4]))  # False

# Approach 2: Counting occurrences (useful for related problems)
def count_elements(nums):
    counts = {}
    for num in nums:
        # If key exists, add 1. If not, start at 0 then add 1.
        counts[num] = counts.get(num, 0) + 1
    return counts

print(count_elements([1, 2, 2, 3, 3, 3]))
# {1: 1, 2: 2, 3: 3}

# Bonus: Find the most frequent element
def most_frequent(nums):
    counts = count_elements(nums)
    max_count = 0
    result = nums[0]
    for num, count in counts.items():
        if count > max_count:
            max_count = count
            result = num
    return result

print(most_frequent([1, 2, 2, 3, 3, 3]))  # 3
```

## Hash Map vs. Set — When to Use Which

You might wonder: should I use a `dict` or a `set`?

| Use a **set** | Use a **dict** (hash map) |
|---|---|
| You only care about *existence* | You need to store *extra info* with each key |
| "Have I seen this number?" | "What index was this number at?" |
| "Is this word in my list?" | "How many times does this word appear?" |

Both give you O(1) lookups. A set is just a hash map without values.

```python
# Set example — just tracking existence
seen = set()
seen.add(5)
print(5 in seen)  # True
```

**Rule of thumb for LeetCode**: If the problem asks for indices, counts, or any associated data — use a dict. If you just need to track "seen or not" — a set is cleaner.

## Key Takeaways

- Hash maps (Python dicts) give you O(1) lookups — turning O(n²) brute-force solutions into O(n) optimal solutions.
- The 'complement lookup' pattern (as in Two Sum) is one of the most common hash map techniques on LeetCode: for each element, check if its needed partner already exists in the map.
- Use hash maps for counting occurrences, tracking seen elements, and mapping values to indices or other data.
- When you only need to check existence (yes/no), a set is a simpler alternative to a full hash map.
- Always ask yourself: 'Am I doing a repeated search inside a loop?' — if yes, a hash map can probably speed it up.
