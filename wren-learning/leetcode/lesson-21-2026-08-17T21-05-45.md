## What Is a Graph?

A **graph** is a collection of **nodes** (also called vertices) connected by **edges**. Think of it like a social network:

- Each person is a **node**
- Each friendship is an **edge**

Graphs are different from trees in important ways:

| Feature | Tree | Graph |
|---------|------|-------|
| Has a root? | Yes | No |
| Can have cycles? | No | Yes |
| One path between nodes? | Yes | Can have many |
| Parent-child relationship? | Yes | Just neighbors |

**Types of graphs:**
- **Undirected**: Edges go both ways (like Facebook friendships — if A is friends with B, B is friends with A)
- **Directed**: Edges have a direction (like Twitter follows — A can follow B without B following A)
- **Weighted**: Edges have values (like distances between cities on a map)

Graphs appear everywhere: road networks, internet routing, recommendation systems, and *tons* of LeetCode problems.

## How to Represent a Graph in Code

The most common way to represent a graph in LeetCode problems is an **adjacency list** — a dictionary where each key is a node and its value is a list of its neighbors.

Imagine this small network:
```
0 --- 1
|     |
3 --- 2
```

As an adjacency list:
```
{
  0: [1, 3],
  1: [0, 2],
  2: [1, 3],
  3: [0, 2]
}
```

Each node lists who it's connected to. Since this is undirected, if 0 connects to 1, then 1 also connects to 0.

**Common input formats on LeetCode:**
1. **Edge list**: `edges = [[0,1], [1,2], [2,3], [3,0]]` — you build the adjacency list yourself
2. **Adjacency list given directly**
3. **Grid/matrix**: A 2D array where cells are nodes and neighbors are adjacent cells (we'll cover this in a future lesson)

## Building an Adjacency List from an Edge List

```python
from collections import defaultdict

def build_graph(edges):
    """Convert an edge list into an adjacency list."""
    graph = defaultdict(list)
    
    for a, b in edges:
        graph[a].append(b)  # a connects to b
        graph[b].append(a)  # b connects to a (undirected)
    
    return graph

# Example
edges = [[0, 1], [1, 2], [2, 3], [3, 0]]
graph = build_graph(edges)

for node, neighbors in graph.items():
    print(f"Node {node} -> {neighbors}")

# Output:
# Node 0 -> [1, 3]
# Node 1 -> [0, 2]
# Node 2 -> [1, 3]
# Node 3 -> [0, 2]
```

## BFS on a Graph — The Key Difference from Trees

You already know BFS from tree traversal (Lesson 14). Graph BFS works the same way — use a queue and process level by level. But there's **one critical difference**:

**Graphs can have cycles!**

Imagine walking through a circular hallway. Without tracking where you've been, you'd walk forever. In a graph, if node 0 connects to node 1, and node 1 connects back to node 0, BFS without tracking would loop infinitely.

**The fix: Use a `visited` set.** Before adding a node to the queue, check if you've already seen it.

**BFS Graph Template:**
1. Start with a node in the queue and mark it visited
2. Pop from the queue
3. For each neighbor, if NOT visited, mark visited and add to queue
4. Repeat until queue is empty

## LeetCode Problem: Find if Path Exists in Graph (LeetCode #1971)

```python
# Problem: Given n nodes (0 to n-1), an edge list, a source, and
# a destination, return True if a path exists from source to destination.

# Example:
# n = 6, edges = [[0,1],[0,2],[3,5],[5,4],[4,3]]
# source = 0, destination = 5 -> False (0 is not connected to 5)
# source = 3, destination = 5 -> True  (3 -> 5)

from collections import defaultdict, deque

def validPath(n, edges, source, destination):
    # Step 1: Build the adjacency list
    graph = defaultdict(list)
    for a, b in edges:
        graph[a].append(b)
        graph[b].append(a)
    
    # Step 2: BFS from source
    queue = deque([source])
    visited = set([source])  # Mark source as visited immediately
    
    while queue:
        node = queue.popleft()
        
        # Step 3: Check if we reached destination
        if node == destination:
            return True
        
        # Step 4: Explore neighbors
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)       # Mark BEFORE adding to queue
                queue.append(neighbor)
    
    # If queue is empty and we never found destination
    return False

# Test cases
print(validPath(6, [[0,1],[0,2],[3,5],[5,4],[4,3]], 0, 5))  # False
print(validPath(6, [[0,1],[0,2],[3,5],[5,4],[4,3]], 3, 5))  # True
print(validPath(3, [[0,1],[1,2],[2,0]], 0, 2))               # True
```

## Why Mark Visited BEFORE Adding to Queue?

This is a subtle but important optimization. Consider this scenario:

```
Node 0 connects to: [1, 2]
Node 1 connects to: [3]
Node 2 connects to: [3]
```

If you mark visited only when *popping* from the queue:
1. Process node 0 → add neighbors 1 and 2
2. Process node 1 → add neighbor 3
3. Process node 2 → add neighbor 3 **again!** (not yet marked visited)

Node 3 gets processed twice! By marking visited **when adding to the queue**, you prevent duplicates.

**Common mistake on LeetCode:** Marking visited too late causes Time Limit Exceeded (TLE) errors on large graphs.

**Time Complexity:** O(V + E) where V = vertices, E = edges. We visit each node once and look at each edge once.

**Space Complexity:** O(V) for the visited set and queue.

## Key Takeaways

- A graph is nodes connected by edges — unlike trees, graphs can have cycles and no root node
- The adjacency list (dictionary of node -> list of neighbors) is the most common way to represent graphs on LeetCode
- Graph BFS is identical to tree BFS but requires a 'visited' set to avoid infinite loops in cycles
- Always mark nodes as visited BEFORE adding them to the queue to avoid processing duplicates
- The pattern of 'build graph + BFS with visited set' solves a huge category of LeetCode problems
