## Why Binary Search Matters

Imagine you're looking for a word in a dictionary. You wouldn't start at page 1 and flip through every page — you'd open the dictionary roughly in the middle, check if your word comes before or after that page, and then repeat with the correct half.

That's exactly what **binary search** does! Instead of checking every element one by one (linear search, O(n)), binary search **cuts the search space in half** each time, giving us O(log n) time.

**How fast is O(log n)?**
- In a list of 1,000 items: ~10 steps instead of 1,000
- In a list of 1,000,000 items: ~20 steps instead of 1,000,000

**Key requirement:** The data must be **sorted**. If it's not sorted, binary search won't work.

In previous lessons, we solved problems using hash maps and two pointers. Binary search adds another essential tool — it's especially useful when dealing with sorted arrays, search problems, or when you need to optimize brute-force solutions.

## The Binary Search Pattern

Every binary search follows the same recipe:

1. **Set two pointers:** `left` at the start, `right` at the end
2. **Find the middle:** `mid = (left + right) // 2`
3. **Compare the middle element to your target:**
   - If `nums[mid] == target` → found it! Return `mid`
   - If `nums[mid] < target` → target is in the **right half**, move `left = mid + 1`
   - If `nums[mid] > target` → target is in the **left half**, move `right = mid - 1`
4. **Repeat** until `left > right` (meaning the target doesn't exist)

**Visual walkthrough** — searching for `7` in `[1, 3, 5, 7, 9, 11]`:

```
Step 1: left=0, right=5, mid=2 → nums[2]=5 < 7 → move left to 3
Step 2: left=3, right=5, mid=4 → nums[4]=9 > 7 → move right to 3
Step 3: left=3, right=3, mid=3 → nums[3]=7 == 7 → FOUND at index 3!
```

Only 3 steps to search 6 elements!

## LeetCode #704: Binary Search — Solution

```python
# LeetCode 704: Binary Search
# Given a sorted array and a target, return the index of the target.
# If not found, return -1.
# Must run in O(log n) time.

def search(nums, target):
    left = 0
    right = len(nums) - 1
    
    while left <= right:  # Keep searching while the window is valid
        mid = (left + right) // 2  # Find the middle index
        
        if nums[mid] == target:
            return mid  # Found the target!
        elif nums[mid] < target:
            left = mid + 1  # Target is in the right half
        else:
            right = mid - 1  # Target is in the left half
    
    return -1  # Target not found

# Example 1: Target exists
print(search([-1, 0, 3, 5, 9, 12], 9))  # Output: 4

# Example 2: Target doesn't exist
print(search([-1, 0, 3, 5, 9, 12], 2))  # Output: -1

# Example 3: Single element
print(search([5], 5))  # Output: 0
```

## Common Pitfalls and Tips

Binary search looks simple but has famous gotchas:

**1. The `<=` vs `<` in the while loop**
- Use `while left <= right` when searching for an exact value. This ensures you check the last remaining element when `left == right`.
- If you use `while left < right`, you might miss the case where the target is at the final narrowed-down position.

**2. Integer overflow with `mid` calculation**
- In some languages (C++, Java), `(left + right)` can overflow. The safe version is: `mid = left + (right - left) // 2`
- In Python, integers can be arbitrarily large, so this isn't a problem — but it's good practice.

**3. Moving pointers correctly**
- Always use `mid + 1` and `mid - 1` (not just `mid`). Otherwise you might get stuck in an infinite loop because the search space never shrinks.

**4. When to think "binary search":**
- The input is **sorted** (or has a monotonic property)
- The problem asks for O(log n) time
- You're searching for a specific value or boundary

## Comparing Linear Search vs Binary Search

```python
# Let's see the difference in number of steps

def linear_search(nums, target):
    steps = 0
    for i in range(len(nums)):
        steps += 1
        if nums[i] == target:
            return i, steps
    return -1, steps

def binary_search_with_steps(nums, target):
    steps = 0
    left, right = 0, len(nums) - 1
    while left <= right:
        steps += 1
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid, steps
        elif nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1, steps

# Search in a list of 1000 elements
nums = list(range(1000))  # [0, 1, 2, ..., 999]
target = 873

idx1, steps1 = linear_search(nums, target)
idx2, steps2 = binary_search_with_steps(nums, target)

print(f"Linear search: found at index {idx1} in {steps1} steps")
# Output: Linear search: found at index 873 in 874 steps

print(f"Binary search: found at index {idx2} in {steps2} steps")
# Output: Binary search: found at index 873 in 10 steps

# 874 steps vs 10 steps — that's the power of binary search!
```

## Key Takeaways

- Binary search works on SORTED data by repeatedly cutting the search space in half, achieving O(log n) time complexity.
- The template uses three variables (left, right, mid) and a while loop with `left <= right` — memorize this pattern as it appears in many interview problems.
- Always move pointers with `mid + 1` or `mid - 1` to avoid infinite loops, and use `<=` in the while condition to check all elements.
- Whenever a problem involves sorted data or asks for O(log n) performance, think binary search immediately.
