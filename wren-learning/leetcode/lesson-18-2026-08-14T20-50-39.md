## DFS vs BFS — Two Ways to Explore a Tree

In lesson 17, we explored trees by diving deep into one branch before backtracking — that's **Depth-First Search (DFS)**. Today we learn the other major approach: **Breadth-First Search (BFS)**.

Imagine you're pouring water on top of a tree. The water doesn't rush down one branch — it spreads across each level before flowing to the next. That's BFS!

- **DFS**: Goes deep first (uses a stack or recursion)
- **BFS**: Goes wide first (uses a **queue**)

BFS is perfect when you need to:
- Process nodes level by level
- Find the shortest path in an unweighted structure
- Compare nodes at the same depth

## What Is a Queue and Why BFS Needs It

A **queue** is like a line at a coffee shop — the first person in line gets served first (**FIFO: First In, First Out**).

Here's why BFS uses a queue:
1. Start by putting the root node in the queue
2. Take the front node out, process it
3. Add its children to the **back** of the queue
4. Repeat until the queue is empty

Because children go to the back, all nodes at the current level are processed before any nodes at the next level. This guarantees level-by-level order!

In Python, we use `collections.deque` because it provides O(1) operations for adding to the back and removing from the front.

## LeetCode #102: Binary Tree Level Order Traversal

```python
# Problem: Given the root of a binary tree, return the level order
# traversal of its nodes' values (i.e., from left to right, level by level).
#
# Example Tree:
#        3
#       / \
#      9   20
#         /  \
#        15   7
#
# Output: [[3], [9, 20], [15, 7]]

from collections import deque

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def levelOrder(root):
    if not root:
        return []
    
    result = []
    queue = deque([root])  # Start with the root in the queue
    
    while queue:
        level_size = len(queue)  # How many nodes are at this level?
        current_level = []       # Collect values for this level
        
        for _ in range(level_size):  # Process exactly this many nodes
            node = queue.popleft()   # Take from the front
            current_level.append(node.val)
            
            if node.left:
                queue.append(node.left)   # Add children to the back
            if node.right:
                queue.append(node.right)
        
        result.append(current_level)  # One level complete!
    
    return result

# Build the example tree
root = TreeNode(3)
root.left = TreeNode(9)
root.right = TreeNode(20)
root.right.left = TreeNode(15)
root.right.right = TreeNode(7)

print(levelOrder(root))  # [[3], [9, 20], [15, 7]]
```

## Walking Through the Algorithm Step by Step

Let's trace through the example tree `[3, 9, 20, null, null, 15, 7]`:

**Iteration 1:**
- Queue: `[3]` → level_size = 1
- Process node 3, add children 9 and 20
- current_level = `[3]`
- Queue after: `[9, 20]`

**Iteration 2:**
- Queue: `[9, 20]` → level_size = 2
- Process node 9 (no children), process node 20 (add 15 and 7)
- current_level = `[9, 20]`
- Queue after: `[15, 7]`

**Iteration 3:**
- Queue: `[15, 7]` → level_size = 2
- Process node 15 (no children), process node 7 (no children)
- current_level = `[15, 7]`
- Queue after: `[]` → empty, we stop!

**Result:** `[[3], [9, 20], [15, 7]]` ✅

The key trick is `level_size = len(queue)`. This snapshot tells us exactly how many nodes belong to the current level, even though we're adding next-level nodes to the same queue during the loop.

## Bonus: Variations You'll See on LeetCode

```python
# LeetCode #107: Bottom-Up Level Order (reverse the result)
def levelOrderBottom(root):
    result = levelOrder(root)  # Reuse our solution!
    return result[::-1]  # Just reverse it
    # Output: [[15, 7], [9, 20], [3]]

# LeetCode #199: Binary Tree Right Side View
# (return the last node at each level)
def rightSideView(root):
    if not root:
        return []
    
    result = []
    queue = deque([root])
    
    while queue:
        level_size = len(queue)
        for i in range(level_size):
            node = queue.popleft()
            if i == level_size - 1:  # Last node in this level!
                result.append(node.val)
            if node.left:
                queue.append(node.left)
            if node.right:
                queue.append(node.right)
    
    return result
    # For our tree: [3, 20, 7] (rightmost at each level)

# Same BFS template, small tweaks = different problems solved!
```

## Key Takeaways

- BFS uses a queue (FIFO) to traverse a tree level by level, while DFS (lesson 17) uses recursion/stack to go deep first.
- The key BFS trick is capturing `level_size = len(queue)` before processing each level — this separates levels cleanly even though they share one queue.
- The BFS template is incredibly reusable: problems like level order, right side view, zigzag traversal, and finding tree width all use the same core pattern with minor modifications.
- Time complexity is O(n) and space complexity is O(n) — you visit every node once, and the queue holds at most one level of nodes at a time.
