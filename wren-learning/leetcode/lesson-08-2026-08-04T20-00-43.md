## The Problem with Searching Through Lists

In previous lessons, we used loops to search through arrays. But what happens when we need to check "have I seen this value before?" or "how many times did this appear?" Using a loop to search means checking every element — that's O(n) each time.

Imagine you have a phone book with 10,000 names. Looking up someone by scanning every page is slow. But if you know to jump directly to the "S" section for "Smith," that's *much* faster.

**Hash maps work like that magic jump.** They let you store and retrieve values in O(1) — constant time — instead of scanning through everything.

In Python, hash maps are called **dictionaries** (`dict`). You've probably seen them before, but today we'll learn to wield them as a problem-solving weapon.

## Dictionary Basics — The Essential Operations

A dictionary stores **key-value pairs**. Think of it like labeled boxes:

- **Create:** `my_dict = {}`
- **Add/Update:** `my_dict[key] = value`
- **Look up:** `my_dict[key]` returns the value
- **Check if key exists:** `key in my_dict` → True/False (this is O(1)!)
- **Delete:** `del my_dict[key]`
- **Get with default:** `my_dict.get(key, default_value)` — won't crash if key missing

The magic is that `key in my_dict` is **instant** (O(1)), whereas `value in my_list` requires scanning the whole list (O(n)).

This single difference is what makes hash maps so powerful on LeetCode.

## Example: Counting Character Frequencies

```python
# Count how many times each character appears in a string
def count_chars(s):
    freq = {}  # empty dictionary
    
    for char in s:
        if char in freq:
            freq[char] += 1  # seen before, increment
        else:
            freq[char] = 1   # first time seeing it
    
    return freq

print(count_chars("hello"))
# Output: {'h': 1, 'e': 1, 'l': 2, 'o': 1}

# Cleaner version using .get()
def count_chars_v2(s):
    freq = {}
    for char in s:
        freq[char] = freq.get(char, 0) + 1
    return freq

print(count_chars_v2("banana"))
# Output: {'b': 1, 'a': 3, 'n': 2}
```

## LeetCode Problem: Two Sum — Revisited with Hash Maps

Remember **Two Sum** from Lesson 2? We solved it with nested loops (O(n²)). Now let's solve it the *right* way — the way interviewers actually want to see.

**The key insight:** As we walk through the array, for each number we ask: "Have I already seen the number that would complete my target sum?"

- We're looking at number `num`. We need `target - num` to exist.
- Instead of looping through the array again to find it, we **look it up in a hash map** in O(1).
- After checking, we store `num` and its index in the hash map for future elements to find.

This is called the **complement pattern** — one of the most common hash map techniques on LeetCode.

## Two Sum — Optimal O(n) Solution

```python
def two_sum(nums, target):
    seen = {}  # value -> index
    
    for i, num in enumerate(nums):
        complement = target - num
        
        if complement in seen:        # O(1) lookup!
            return [seen[complement], i]
        
        seen[num] = i  # store this number for later
    
    return []  # no solution found

# Walk through example: nums = [2, 7, 11, 15], target = 9
# 
# i=0, num=2: complement=7, seen={} → 7 not in seen → seen={2:0}
# i=1, num=7: complement=2, seen={2:0} → 2 IS in seen! → return [0, 1] ✓

print(two_sum([2, 7, 11, 15], 9))   # [0, 1]
print(two_sum([3, 2, 4], 6))        # [1, 2]
print(two_sum([3, 3], 6))           # [0, 1]

# Time: O(n) — one pass through the array
# Space: O(n) — storing up to n elements in the hash map
```

## Bonus Problem: Contains Duplicate (LeetCode #217)

```python
# Given an array, return True if any value appears at least twice.
# 
# Brute force: compare every pair → O(n²)
# Hash map: track what we've seen → O(n)

def contains_duplicate(nums):
    seen = set()  # a set is like a dict but keys only, no values
    
    for num in nums:
        if num in seen:     # O(1) lookup
            return True
        seen.add(num)
    
    return False

print(contains_duplicate([1, 2, 3, 1]))     # True
print(contains_duplicate([1, 2, 3, 4]))     # False
print(contains_duplicate([1, 1, 1, 3, 3]))  # True

# Even simpler one-liner (but less educational):
def contains_duplicate_v2(nums):
    return len(nums) != len(set(nums))

# Note: A set is perfect when you only need to track 
# "have I seen this?" without storing extra info like indices.
```

## Key Takeaways

- Hash maps (dictionaries) give you O(1) lookups — checking 'is this key in my dict?' is instant, unlike scanning a list which is O(n)
- The 'complement pattern' (storing values as you go, checking for the needed partner) is one of the most common LeetCode techniques and turns O(n²) solutions into O(n)
- Use a dictionary when you need to map values to extra info (like indices); use a set when you just need to track 'seen or not seen'
- The trade-off: hash maps use extra memory (O(n) space) to gain speed — this is almost always worth it on LeetCode
